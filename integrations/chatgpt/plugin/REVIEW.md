# Prepare the Tendriller directory review

The upload package is generated by `node integrations/chatgpt/plugin/build.mjs`.
Its output is `dist/tendriller-chatgpt-plugin.zip`. The public listing currently
names Gabriel Pickard as the publisher. Confirm that this matches the verified
publisher identity selected in the portal.

## Dedicated account and live sample

Provision the dedicated sample account through the operator's private magic URL.
It uses a normal Tendriller account and session, then the same application and
OAuth approvals. Reviewers can use it without an upstream provider account.
The same mechanism is available for our live browser tests.

Run `node scripts/provision-test-access.mjs --config server/wrangler.staging.jsonc
--output /private/path/staging-test-access.json --days 30` from the repository
root. Choose the production config and a different private output path for a
production account. The script saves the private URL and synthetic owner email
identity locally and configures only the token hash in the Worker. Open its saved
`url`, then select **Open test account**. Use the synthetic account email
`ACCOUNT_ID@example.invalid` from that record when creating the sample page.
The owner claims and approves that page through the normal browser flow.

The reusable link expires after the selected period. Keep it in the private
OpenAI review form or local test configuration. To revoke it, rerun the same
provisioning command with `--revoke`; this also suspends its sample account and
revokes its browser sessions and OAuth grants. Create a new output record for a
new account after revocation. All testers using the link share sample state.

Use the adjacent `review-domain.mjs` as the application definition. Its initial
query `checklist` returns two incomplete items, `check-labels` and `check-links`.
Its only command is `completeItem`, with the exact item ID. It exposes no delete
or reset command. Configure the application using the normal
[first-app lifecycle](../../../docs/BUILD_AN_APP.md). The existing host setup,
participant, and signed publication APIs apply to this sample.

Enroll an assistant connection named **Review checklist** with query
`checklist`, command `completeItem`, and event `item.completed`. Forward native
events from topic `completed`, projecting each payload to
`{ name: 'item.completed', payload: { id: event.payload.id } }` with the normal
durable `forwardApplicationEvents` checkpoint. Give the owner the real proposal
review URL. The enrolled native participant must remain available during review.
Save its private handle, device, keys, event cursor and resume command outside
the package. App setup is pending until this lifecycle is completed and verified.

Keep a second account outside the review app to check account isolation. Do not
grant the reviewer access to real users' apps or data. After completing Check
labels, its state stays complete. Use a fresh sample app for a new clean review
run, or explicitly document that the item is already complete.

## Record and run the review cases

Run the five positive cases and three negative cases from
`plugin.json` in the actual ChatGPT plugin using the dedicated review account.
Capture a browser recording showing account linking, listing and describing the
sample, reading Check labels, approving completion, a fresh read, and the
retained completion event. Show how an ambiguous command, unsupported deletion,
and an attempt to access another account's app are handled.

The recording should show observable results and the tools used. Keep sign-in
secrets, OAuth codes and tokens out of the recording. Provide an accessible video
URL in **Metadata & Skills → Review information → Review details**. The cases in
the ZIP are proposed review procedures. A package build does not establish that
they passed in ChatGPT.

Enter the private magic URL, the **Open test account** step, the
selected ChatGPT plugin, the actual app name, and participant availability in the
private review form. Verify the reviewer can complete the steps before
submission. Keep the account, sample app and participant available for later
reviews as well.

## Portal sequence

1. Complete publisher verification at
   [Organization settings](https://platform.openai.com/settings/organization/general).
2. Upload the ZIP through **Upload new or existing plugin** at
   [Platform Plugins](https://platform.openai.com/plugins), selecting the verified
   identity and publishing project.
3. Open **MCPs → tendriller → Connect**. Verify it uses
   `https://tendriller.dev/mcp` and CIMD OAuth. Give the service operator the
   exact domain challenge URL and public token if requested. Wait for the
   operator to verify its exact plain-text response, then complete linking.
4. Resolve required metadata, skill and tool findings. Complete **Review
   details** with the dedicated credentials and recording. Check the imported
   five positive and three negative cases.
5. Submit for review and complete the publisher's required attestations. After
   approval, publish. Record the actual public install link in the user setup
   guide and test it from an account outside the publisher's workspace.

OpenAI documents the current requirements in the
[submission guide](https://developers.openai.com/plugins/deploy/submission).
