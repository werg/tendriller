## Prepare and publish before the first browser key exists

```sh
npm run setup:prepare -- https://YOUR_SELECTED_SERVICE "Shared notes"
# Call prepare_tendril_setup through the same linked connector using the exact
# printed PUBLIC arguments; retain the original private intent.
npm run setup:finish -- .tendriller/account-setup-result.json
npm run init
npm run deploy
# Give the owner the returned ready page URL now. They complete their own sign-in.
```

After a lost setup reply, use `inspect_tendril_setup` on the same original operation. No replacement intent, local OAuth token or claimed reply is needed. The domain-only `create` route remains available for the actual owner's verified email, under the same selected service readiness.

`init` retains only an independent publisher key and `HostAppConfig`. It creates no native data device, data root, epoch key, immutable schema or application-order authority. `deploy` signs the entire dedicated `page/` graph and retains the exact publication attempt before sending. **No native participant is needed for browser Save.** Private `.tendriller/` records never enter authored output.

## Owner browser and additional devices

The signed-in first browser proves its key and initializes the descriptor root, initial membership and epoch-key commitment. The actual epoch key is durably local before the proof and resumes after uncertain replies. Existing devices open cached local identity/authority/keys/data before optional background refresh/discovery.

A fresh second browser starts keyless. Create its public provisioning request, review the full recipient fingerprint on an existing authorized device, grant exact independent crypto rights, wrap keys to that recipient, then import its package. The agreement secret stays in the original owning Worker. Host login alone never decrypts old data. Crypto membership does not imply SQL namespace/object/row/column permission.

Keep the same `helpers/browser-profile.mjs` profile on every document. One SharedWorker or Web-Lock-elected Worker owns the physical signer/store; view/root lifetimes do not allocate global application order. Detach a view, not another tab's owner. Restore missing private records rather than silently replacing keys or stores.

## Author and derive locally

`domain.mjs` declares ordinary create/edit/delete note commands. `deriveNotes(view)` derives the complete current domain from one coherent materialized event snapshot. The page renders stable-ID list/detail plus separate local editor drafts and deep links. Incoming earlier work may reorder/remove/revise notes without overwriting unsent text or focus.

Submission resolves after exact local durable storage. Inspect **stored**, **materialized locally (revisable)**, **retained by named peers**, **finalized**, and **excluded** separately. Retention/finality are not execution acknowledgments. `operations.retry(id)` uses the original signed bytes/time/identity; uncertain RPC replies never authorize a replacement ID or timestamp.

The default finality policy is `none`; finality waits explicitly fail as unsupported. `init -- --browser-finalizer` deliberately chooses signed-frontier policy on a new app. Its actual authorized browser provider must be exercised before claiming availability. Closing author time can exclude genuine unseen offline work behind the frontier; retain its original intent visibly. Missing providers, agents, peers or a current global read never gate ordinary local Save.

Save the **complete immutable app graph** and wait for its service-worker acknowledgment before reporting offline readiness. Then disconnect, reload, CRUD and inspect with the same local identity. An installed adapter or cached HTML alone is insufficient.

## Optional native tools/media

`session.mjs` is an optional additional native profile using the same public session, private IPC supervisor and direct RTC/relay controller. It never initializes the app root or invents a missing epoch key. Use its explicit `init-device`, `sign-enrollment`, `provisioning-request`, and `import-provisioning` commands, then run it only for features that need that process. Browser edits continue when it stops. See the selected service's [CLI guide](https://tendriller.dev/docs/tools/CLI.md).

Optional camera/voice/content/inference modules preserve acquisition, explicit sharing consent, editable review and durable commit boundaries. Missing inference disables analysis only. Provisional claims/results cannot authorize irreversible external effects. The main page's file preview sends nothing automatically.
