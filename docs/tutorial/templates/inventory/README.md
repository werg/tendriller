# Inventory workspace page

Create with `npm run page:new -- stock --template inventory`, prepare with `npm run init -- stock`, and publish with `npm run deploy -- stock`. This uses the workspace's existing opaque shared signer and explicit host page grant. It creates no native data device, epoch key, SQL schema or ordering state and never requires a running `tendril agent run`.

Choose the exact immutable SQL/browser session composition and its four package-public WASM assets. Preflight and init verify/copy that graph without a native SQL addon or supplemental download. The owner opens the signed page and completes account/key enrollment. The first browser initializes its root/membership and retains actual keys locally. Additional devices need explicit recipient-bound key provisioning; crypto membership is separate from ordinary SQL grants.

The UI authors ordinary atomic CREATE/ALTER/DML/permission programs. Initialize tables, add labels, create an author-owned bin, review balances and transfer units. A crypto writer can create its own rows but cannot update another author's bins without a deliberate SQL column grant. Adding label does not expand an older units-only grant. Late earlier operations can revise execution, rows and schema; counts, catalog and details rederive from one captured snapshot while local drafts, stable selection and focus remain independent.

Local Save depends on signing/storage/key prerequisites, not a successful query, peer, native agent, inference service or finalizer. Stored intent is not materialized success, named-peer retention or finality. Preserve original IDs/author times/signed bytes on retry. Finality is `none` unless explicitly chosen; closure can exclude unseen work behind its sealed frontier.

For optional native SQL, explicitly provision the SAME workspace signer separately for this page using the root workspace commands. Importing the verified package creates the native eligibility marker; only then may the single agent program open the page with its matching native SQL capability. The optional `npm run demo -- stock` attaches to that program, reads once and detaches—it never creates another root or special schema. Other pages may use the same signer with independent grants/keys.

Qualification must include actual browser-only setup, offline CRUD/reload, separate-browser crypto and SQL grants, guarded transfer, schema-only invalidation, earlier DDL outcome revision, visible operation facts and desktop/320px keyboard/long-content/error states. Native or HTML-only checks are not browser/WASM qualification. Report exact artifacts and untested Internet NAT, OAuth, physical device and provider boundaries. Production rollout is separate.
