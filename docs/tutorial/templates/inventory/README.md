# Inventory workspace page

Create with `npm run page:new -- stock --template inventory`, prepare with `npm run init -- stock`, and publish with `npm run deploy -- stock`. This uses the workspace's existing opaque shared signer and explicit host page grant. `init` creates the page keys with the agent as creator (no SQL schema or ordering state, and no native SQL addon); `--browser-first` leaves creation to the owner's first browser.

Choose the exact immutable SQL/browser session composition and its four package-public WASM assets. Preflight and init verify/copy that graph without a native SQL addon or supplemental download. The owner opens the signed page and signs in; an online member (the running `npm run agent`, or an admitted device) admits the browser and wraps its keys. Additional devices and invited people are admitted the same way; membership is separate from ordinary SQL grants.

The UI authors ordinary atomic CREATE/ALTER/DML/permission programs. Initialize tables, add labels, create an author-owned bin, review balances and transfer units. A crypto writer can create its own rows but cannot update another author's bins without a deliberate SQL column grant. Adding label does not expand an older units-only grant. Late earlier operations can revise execution, rows and schema; counts, catalog and details rederive from one captured snapshot while local drafts, stable selection and focus remain independent.

Local Save depends on signing/storage/key prerequisites, not a successful query, peer, native agent, inference service or finalizer. Stored intent is not materialized success, named-peer retention or finality. Preserve original IDs/author times/signed bytes on retry. Finality is `none` unless explicitly chosen; closure can exclude unseen work behind its sealed frontier.

The single agent program opens this page with its matching native SQL capability once `init` has written `initialized.json`. Membership grants no SQL permission: before that participant updates units or records transfers, an authorized browser grants its key with the ordinary “Grant units updates and receipt inserts” transaction; otherwise its writes are rejected with `policy:inventory:update`. Until it has replicated the initializing transaction, its `inventory` query reports a missing-table view error, not empty data. The optional `npm run demo -- stock` attaches to that program, reads once and detaches—it never creates another root or special schema. Other pages may use the same signer with independent membership and keys.

Native or HTML-only checks are not browser/WASM qualification. Report exact artifacts and untested Internet NAT, OAuth, physical device and provider boundaries. Production rollout is separate.
