# Public service implementation status

Updated 2026-11-14. The repository has one public-service code path. Both domains, OAuth providers, Turnstile, D1 and R2 resources, secrets, legal pages, and Workers are deployed. Staging creation is **open** for testing with friends. Production creation is **open** as of 2026-11-14. Real production GitHub and Google sign-in completion and automatic owner claim still need browser verification.

## Implemented and checked

- Service and per-page origins, page sessions, Origin checks, HSTS, GitHub/Google OAuth with PKCE, verified email matching, automatic owner claim on page open, guest approval, owner-only display links, and agent revocation.
- Account dashboard, provider linking, export, deletion, page-scoped agent tokens, per-account and service byte reservations, global creation admission, rate limits, and service state controls. Account keys and the device authorization flow have been removed.
- Reports, Turnstile, static version screening, automatic holds and suspension, in-app notices, page/account appeals, admin actions, audit log, and sensor history.
- On-device speech input and neural speech output with pinned model assets, fallback and recovery behavior, provisioning scripts, CI, legal pages, and operational runbooks. Speech model loading passes the WASM `i64` length as `BigInt`; microphone decoding uses `OfflineAudioContext`.
- Local TypeScript checks, 19 Worker tests, 14 local headless browser tests, and 13 speech-output browser tests pass. The browser suite covers automatic claim, listener requirements, event delivery, page replies, presence, origin isolation, microphone startup, neural speech playback, interruption, and recovery. The opt-in test also initializes the pinned Cactus WASM and Whistle model in Chromium and transcribes silence.
- The live staging API created, published, redirected, and deleted a temporary page successfully. The user confirmed staging GitHub sign-in, linking Google to that account, and opening an agent-created page without a Claim step. A page tap and typed instruction appeared in `GET A/events`; an agent `POST A/say` reply reached the page and played as voice. The staging and production guides and health endpoints were checked live; retired routes were checked on staging.
- The agent guide now starts with page ideas and the create/publish/converse loop. The page sends UI and sensor data with `tendril.send`; the agent replies through the built-in conversation with `POST A/say`. The first page publication requires a live event poll or configured wake receiver, and every poll response includes a next-poll reminder.
- A Codex-on-Linux bridge attaches a page to the creating conversation, keeps a background poll, and queues a count-only wake notice. A local fault-injection test covers retry, coalescing, and explicit acknowledgement. A staging owner tap woke this idle Codex conversation; the agent read the event, published a new page version, updated shared state, sent a spoken reply, and acknowledged the event. Version 2 became healthy and the connected browser showed the new card. The earlier scripted responder page was a separate test and did not prove this path.
- A Claude Code channel adapter attaches a private handle to the session that called its tool, long-polls events, emits count-only channel notices, exposes event-read and acknowledgement tools, and stops on detach. A local MCP protocol test covers attach, repeated wake, read, ack, and no token/page-content leak. A real Claude Code v2.1.325 session was left idle; a local test API then queued an owner instruction, which woke that same session. Claude read it, posted a reply to `/say`, and acknowledged sequence 1. A staging page-to-session test remains. Custom channels currently require a research-preview development opt-in and the session to remain open.
- An OpenClaw-on-Linux bridge polls a page and submits a count-only `system event --mode now` to an explicit agent-qualified session key. A fault-injection test covers failed admission, retry, coalescing, acknowledgement, and no page-data leakage. A real OpenClaw Gateway turn remains untested; no working OpenClaw installation is available in this workspace.
- The Claude channel bundle, OpenClaw bridge, and revised agent guide were deployed to staging and production; direct GET checks returned HTTP 200 on both service domains. Production creation was paused at that point.
- Long-poll requests now support up to five minutes (`wait=300`), and the bundled listeners use a 330-second client timeout for those requests. A waking event still returns immediately; reconnection after a quiet timeout is required. A fresh staging page returned HTTP 400 for `wait=301` after deployment. A previously active page still returned the old response immediately after deployment because Cloudflare defers code updates for active Durable Objects for up to five minutes by default; the bridge retries through an instance reset.

A Linux Hermes bridge submits count-only notices through the externally maintained Wake plugin to its bound chat; local fault-injection tests cover retry, coalescing, ack, and data exclusion, but a real Hermes turn remains unverified. The Muse background wait recipe, Grok Bot bearer routine, Grok automation Standard Webhooks mode, Hermes generic V2 signature mode, dot MCP Events subscription, and Duet polling fallback are documented. Signed webhook configuration and exact-byte HMACs have local tests. No live Muse, Grok, dot, or Duet session was available in this workspace.

## Production activation

On 2026-11-14, the operator explicitly authorized opening production creation. The production D1 `service_state` changed from `creation_paused` to `open`. Both `/auth/github` and `/auth/google` returned redirects with production callback URLs, and `/health` returned OK. A disposable page was created through `https://tendriller.dev/api/tendrils`; its returned hostname was under `tendriller.site`. Its long poll woke on a diagnostic delivery probe, the probe acknowledgement was recorded, and the page was deleted. This verifies server-side creation and routing. Real browser completion of both production OAuth providers and automatic claim remains to be checked.
