# Tendriller protocol and internal contracts

This is the single source of truth for every interface between components. If an
implementation needs to deviate, change this file in the same edit and say why.
`PLAN.md` explains the design; this file pins it down.

Conventions: JSON everywhere unless stated. Times are milliseconds since epoch
(`ts`). Errors are `{"error": {"code": "<snake_case>", "message": "<text>"}}` with
an appropriate HTTP status. Unknown JSON fields are ignored.

---

## 1. Identifiers and secrets

| Name | Format | Secret? | Notes |
|---|---|---|---|
| Tendril id | 12 chars `[a-z2-7]` (base32, 60 bits) | No | Appears in URLs and subdomains. Durable Object is `idFromName(id)`. |
| Page key | 26 chars `[a-z2-7]` (130 bits) | Yes | In the page URL path. One per link (section 6.8). |
| Agent token | `tk_` + 32 chars `[a-z2-7]` | Yes | `Authorization: Bearer <token>`. Stored server-side as SHA-256 hex. Never sent to pages. |
| Device id | `d_` + 16 chars `[a-z2-7]` | No | Generated by the page, kept in `localStorage` key `tendril:<tendrilId>:device`. |
| Device secret | 32 chars `[a-z2-7]` | Yes | Generated with the device id, stored alongside it. Server binds the role to `(device id, sha256(secret))` on first sight. |
| Blob id | `b_` + 20 chars `[a-z2-7]` | No | Access always requires a page key or agent token. |
| Adopt code | `<tendrilId>-<6 digits>` | Yes, short-lived | Valid 10 minutes, single use. |
| Link id | `l_` + 10 chars | No | |

Random values use `crypto.getRandomValues`. Comparisons of secrets use constant-time
comparison of hashes.

## 2. URLs and routing

Environment (`server/wrangler.jsonc` vars):

- `PUBLIC_BASE`: e.g. `https://tendril.example.com` (dev: `http://localhost:8787`).
- `PAGE_HOST_MODE`: `path` (dev default) or `subdomain`.
- `PAGE_BASE_DOMAIN`: for subdomain mode, e.g. `tendril.example.com`. Pages are then
  `https://<id>.<PAGE_BASE_DOMAIN>/s/<pageKey>/` and the deployment needs a wildcard
  route and certificate.

Page base `P`:
- path mode: `${PUBLIC_BASE}/t/<id>/s/<pageKey>/`
- subdomain mode: `https://<id>.<PAGE_BASE_DOMAIN>/s/<pageKey>/`

The server must accept both shapes on every deployment (id from the subdomain if the
Host matches `<id>.<PAGE_BASE_DOMAIN>`, otherwise from the `/t/<id>/` prefix). Agents
never build URLs themselves; the server returns them. `P` always ends in `/`; a
request for `P` without the trailing slash redirects (308) to it.

Agent API base `A = ${PUBLIC_BASE}/api/t/<id>`.

Public, unauthenticated:
- `GET /` → short HTML landing page linking `/agent.md`.
- `GET /agent.md` → the instructions file (static asset).
- `GET /snippets/<name>.js` → snippets (static assets).
- `GET /health` → `{"ok": true}`.

### 2.1 Page routes (all under `P`, authorized by the page key in the path)

| Route | Behaviour |
|---|---|
| `GET P` | Current version's `index.html` with the runtime injected (section 5). If there is no version yet, a built-in holding page (also injected) that says "Waiting for the agent". |
| `GET P<path>` | File `<path>` from the version being served to this request (section 4). 404 if absent. `Cache-Control: no-cache`. |
| `GET P_tendril/tendril.js` | Runtime bundle (static asset `/_tendril/tendril.js`). |
| `GET P_tendril/sw.js` | Service worker (static asset) with header `Service-Worker-Allowed: <path of P>`. |
| `GET P_tendril/ws` | WebSocket upgrade (section 7). |
| `GET P_tendril/info` | `{"id","version","files":[paths],"features":{...}}` for the service worker's cache list. |
| `POST P_tendril/blob` | Raw body upload, `Content-Type` kept, optional header `X-Tendril-Name`. Max 25 MB. → `{"id","url"}` where `url` is page-relative `_tendril/blob/<id>`. Recorded in activity. |
| `GET P_tendril/blob/<id>` | Blob bytes. |
| `GET P_tendril/snippets/<name>.js` | Same as `/snippets/<name>.js`, so pages can use relative URLs. |
| `GET P_tendril/manifest.webmanifest` | Web app manifest from tendril metadata (`name`, `short_name`, `theme_color`, `background_color`, icon); `start_url` and `scope` = `P`. |
| `GET P_tendril/icon` | Icon: the blob named in metadata, else a generated SVG with the first letter of the name. |
| `POST P_tendril/transcribe` | Raw audio body → `{"text"}`. Uses Workers AI binding `AI` if present, else 501 `{"error":{"code":"unavailable"}}`. |
| `POST P_tendril/voice/session` | Fast voice layer session, delegated to `handleVoiceSession` in `server/src/voice.ts` (section 9). |

Paths beginning with `_tendril/` are reserved; agents cannot upload files there.

### 2.2 Agent API

All requests need `Authorization: Bearer <token>` except `POST /api/tendrils`
(needs `Bearer <CREATE_KEY>` only if the `CREATE_KEY` secret is set) and
`POST /api/adopt`. Every authenticated call is a **check-in** (section 8.4).

**Create and adopt**

- `POST /api/tendrils` body `{"name"?, "lifetime"?: "ad_hoc"|"resident", "pairing"?: "open"|"required"}`
  → 201 tendril handle:
  ```json
  {"id":"…","name":"…","page_url":"<P>","api":"<A>","token":"tk_…",
   "agent_md":"<PUBLIC_BASE>/agent.md","lifetime":"ad_hoc","expires_at":<ts|null>}
  ```
  Defaults: name `"Tendril"`, lifetime `ad_hoc`, pairing `open`.
- `POST /api/adopt` body `{"code"}` → 200 tendril handle with a fresh token. All
  previously issued agent tokens of that tendril are revoked.

**Tendril**

- `GET A` → `{"id","name","page_url","lifetime","expires_at","pairing","version":{"current","latest","healthy"},"devices":[device…],"presence":{presence},"wake":{wake config},"meta":{…}}`
- `PATCH A` body any of `{"name","lifetime","pairing","short_name","theme_color","background_color","icon"}` (`icon` is a blob id or an https URL) → same as `GET A`.
- `DELETE A` → 204. Deletes everything (storage, R2 objects); all URLs stop working.

**Files and versions (section 4)**

- `PUT A/files/<path>` raw body, `Content-Type` stored (guessed from extension if
  absent or `application/octet-stream`). Optional query `message`. Creates a new
  version = previous latest version's files + this file. → `{"version","files":[paths]}`.
- `POST A/files` body `{"files":{"<path>": "<utf8 text>" | {"base64":"…","type"?:"…"}}, "delete"?:["path"], "replace"?:bool, "message"?:string}`
  → one new version. `replace: true` means the version holds only the given files.
- `GET A/files` → `{"version","files":[{"path","size","type","hash"}]}` for the current version (or `?version=n`).
- `GET A/files/<path>` → content from the current version (or `?version=n`).
- `GET A/versions` → `{"versions":[{"version","created_at","status":"pending"|"healthy"|"failed","message","files":n,"errors"?:[…]}], "current","latest","healthy"}` newest first.
- `POST A/rollback` body `{"version"?}` → default: newest healthy version older than current. Makes it current, pages reload. → `{"version"}`.

**Events (section 8)**

- `GET A/events?after=<cursor>&wait=<0..25>&limit=<1..500, default 100>`
  → `{"events":[event…],"cursor":<seq>,"timeout"?:true,"withheld":<n>}`
  - `after` default 0. Events have increasing integer `seq`; `cursor` is the last
    returned `seq` (or `after` if none).
  - `wait=0` (default): return all events with `seq > after` immediately.
  - `wait>0`: if any event with `seq > after` has `wake: true`, return immediately
    with all events `> after`. Otherwise hold until such an event arrives (then
    return all events `> after`) or until `wait` seconds pass (then return
    `{"events":[],"cursor":after,"timeout":true}`).
  - While a `wait>0` request is held the agent counts as **listening**.
- Event shape:
  ```json
  {"seq":12,"ts":…,"type":"event"|"instruction"|"version_failed"|"version_healthy"|"device"|"rule"|"voice",
   "data":…,"device":"d_…"|null,"role":"owner"|"guest"|"display"|null,
   "wake":true,"withheld":false,"by":null}
  ```
  - `instruction`: speech or text an **owner** device sent through the control or
    the voice layer: `data = {"text","via":"voice"|"text"|"voice_layer"}`. These are
    the only events that are instructions. Text from guest devices arrives as
    type `event` with `data = {"text","via"}` and `role:"guest"`.
  - `event`: from `tendril.send(data)`. Always data, never instructions.
  - `version_failed`: `data = {"version","errors":[…],"rolled_back_to"}`. Wake once per version.
  - `version_healthy`: `data = {"version"}`, `wake:false`.
  - `device`: `data = {"action":"joined"|"left"|"pair_request","device":{device}}`; `pair_request` wakes, others don't.
  - `rule`: a device rule fired; `data = {"rule_id","detail"}`.
  - `voice`: voice layer handled something itself; `data = {"text","function","args"}`, `wake:false`.
  - `by`: name of the agent token for agent-originated entries (shared tendrils), else null.

**Calling into the page**

- `POST A/eval` body `{"code","device"?: "primary"|"all"|"<device id>","timeout_ms"?:10000}`
  → `{"ok","value"?,"error"?,"device","results"?:[{"device","ok","value"?,"error"?}]}`
  - `code` is the body of an async function (`return document.title`, `await` allowed).
  - `value` is JSON-serialisable; the runtime converts `undefined` to `null`,
    DOM elements to their `outerHTML` truncated to 2000 chars, errors to strings,
    and anything else non-serialisable to `String(x)`.
  - Default target `primary` = most recently active connected owner device (else
    any connected device). `all` fills `results` and mirrors the first into the top level.
  - No connected device → 409 `{"error":{"code":"offline","message":"No device connected; last seen at <ISO>","last_seen":<ts|null>}}`.
  - Timeout → 504 `{"error":{"code":"timeout"}}`.
- `POST A/say` body `{"text","speak"?:true}` → `{"ok":true}`. Shown in the control's
  transcript on all devices; spoken on owner devices if `speak` and the user has not
  muted audio. Also recorded in activity.
- `POST A/status` body `{"text"?,"state"?:"working"|"idle"|"done"}` → `{"presence"}`.
  Overrides the presence label until the next long-poll or 10 minutes.
- `POST A/check` body `{"device"?}` → runs an accessibility audit in the page
  (axe-core loaded from `https://cdn.jsdelivr.net/npm/axe-core@4/axe.min.js`) and
  returns `{"ok","violations":[{"id","impact","help","nodes":n}]}`.

**State (section 3.2)**

- `GET A/state` → `{"rev","state"}`.
- `PUT A/state` body = whole new state object → `{"rev"}`.
- `PATCH A/state` body = JSON Merge Patch (RFC 7396; `null` deletes) **or**
  `{"ops":[{"op":"set","path":["a","b"],"value":…}|{"op":"delete","path":[…]}]}`
  → `{"rev"}`.

**Logs, blobs, devices, links**

- `GET A/logs?after=<seq>&limit=` → `{"logs":[{"seq","ts","device","version","level":"log"|"info"|"warn"|"error","message","stack"?}],"cursor"}`. Keeps the last 2000.
- `PUT A/blobs` raw body (+ optional `X-Tendril-Name`) → `{"id","url"}` (`url` page-relative).
- `GET A/blobs` → `{"blobs":[{"id","type","size","name","ts","device"}]}`; `GET A/blobs/<id>` → bytes.
- `GET A/devices` → `{"devices":[device…]}`; device =
  `{"id","name","role","connected":bool,"primary":bool,"last_seen","ua","link"}`.
- `PATCH A/devices/<id>` body `{"role"?,"name"?}` (approving a pairing = setting role `owner`).
- `DELETE A/devices/<id>` → disconnects and forgets the device.
- `POST A/links` body `{"role":"owner"|"guest"|"display","label"?,"expires_in"?:seconds}` → `{"id","url","role","label","expires_at"}`.
- `GET A/links`, `DELETE A/links/<id>`. The original page URL is link `l_main` (role `owner`), which cannot be deleted, only rotated via `POST A/links/l_main/rotate` → new URL.

**Wake, activity, tokens, rules, notifications**

- `GET A/wake`, `PUT A/wake` body any of
  `{"webhook": {"url","token"?} | null, "schedule_minutes": n | null, "budget": {"owner_per_hour","page_per_hour"}, "grace_seconds": n}`
  → wake config `{"webhook":{"url","has_token"}|null,"schedule_minutes","budget","grace_seconds","withheld":{"owner","page"}}`.
- `GET A/activity?after=&limit=` → `{"entries":[{"seq","ts","kind","summary","device","blob"?,"by"?,"source":"server"|"agent"}],"cursor"}`.
- `POST A/activity` body `{"text"}` → agent note (`source: "agent"`).
- `POST A/tokens` body `{"name"}` → `{"name","token"}` (additional agent token, e.g. for another person's agent). `GET A/tokens` → `{"tokens":[{"name","created_at","last_used"}]}`. `DELETE A/tokens/<name>`. The first token is named `main`.
- `GET A/rules`, `PUT A/rules` body `{"rules":[rule…]}` (section 10).
- `POST A/notify` body `{"title","body"?,"url"?,"device"?,"tag"?}` → `{"sent","failed"}` (web push to subscribed devices with role owner; section 10).

## 3. Server storage model (Durable Object `Tendril`, SQLite)

One Durable Object per tendril, `env.TENDRIL.idFromName(id)`. File bodies and blobs
live in R2 bucket `env.FILES` under `t/<id>/files/<sha256>` and `t/<id>/blobs/<blobId>`.
Everything else is in the object's SQLite storage. Suggested tables (the server
agent owns the exact schema): `meta` (key/value), `tokens`, `links`, `devices`,
`versions`, `version_files`, `events`, `logs`, `blobs`, `activity`, `push_subs`,
`rules`, `dedupe` (client message ids, kept 24 h).

### 3.1 Limits
File 25 MB; blob 25 MB; event `data` 64 KB serialized; state 1 MB serialized;
logs 2000 kept; events 10 000 kept and 30 days; activity 30 days; eval code 256 KB.

### 3.2 State
- One JSON object, revision counter `rev` (+1 per applied change).
- All changes are applied as path operations (`set`/`delete` on a path of string
  keys); merge patches are converted to leaf `set`/`delete` ops. Last writer wins
  per path, in the order the server applies them.
- Every applied change is broadcast to pages as `{"t":"state","ops":[…],"rev","by"}`.
- Reserved top-level keys (agents may write them; the runtime reads them):
  - `_about`: handover note `{"purpose","layout","source"}` for resident tendrils.
  - `_prefs`: user preferences `{"text_size":"normal"|"large"|"x-large","contrast":"normal"|"high","audio":bool,"language":"en-US"}` set from the control.
  - `_device`: `{"<device id>": {…}}` per-device data; `tendril.state.mine()` reads its own entry.
  - `_overlay`: drawing commands for the point-and-ask snippet.

## 4. Versions and health

- A version is an immutable map `path → {hash, type, size}`, numbered 1, 2, 3 …
- Pointers: `latest` (newest), `healthy` (newest healthy), `current` (the one served).
- On upload: new version `n` with status `pending`; `current = n`; all pages get
  `{"t":"reload","version":n}`.
- The runtime reports `{"t":"health","version":n,"ok":bool,"errors":[…]}` once per
  page load: `ok:false` if an uncaught error or unhandled rejection happens before
  `health_ms` (2000 ms after `load`, or immediately on `tendril.ready()` if the page
  called `tendril.ready.manual()` before `load`); `ok:true` otherwise.
- Health reports for a pending version: first `ok:true` → `healthy`, event
  `version_healthy`. First `ok:false` (or no report within 15 s after the version was
  first served to a connected device) → `failed`; if a healthy version exists,
  `current = healthy` and pages reload; event `version_failed` (wake, once per version).
- Serving rule: a request for `P` gets `current` unless `current` is failed, in
  which case it gets `healthy`; no healthy and no current → holding page.
- Pages can include the served version in requests for other files via the
  `?v=<n>` query the runtime adds; without it, files come from `current`.

## 5. Runtime injection

When serving any `.html` file from a version (and the holding page), the server
inserts immediately after the opening `<head …>` tag (or at the very start if there
is no `<head>`):

```html
<script>window.__TENDRIL__={"id":"…","base":"<path of P>","version":n,"ws":"<path of P>_tendril/ws","features":{"transcribe":bool,"voice":bool,"push":bool,"vapid":"<public key>|null"}};</script>
<script src="<path of P>_tendril/tendril.js"></script>
```

`base`, `ws` are absolute paths (no origin). `tendril.js` is synchronous so that
`window.tendril` exists before the page's own scripts run.

## 6. Roles, pairing and links

- Roles: `owner` (speech/text are instructions, can see activity, undo, pairing,
  adoption), `guest` (can use the page; its text is data), `display` (read-only: the
  control hides input; `tendril.send` is dropped server-side).
- Each link has a role. Opening a link with role `guest`/`display` gives that role.
- Opening an `owner` link:
  - pairing `open`: device becomes `owner`.
  - pairing `required`: the first device ever becomes `owner`; later new devices
    become `guest` with `pending: true` and a 6-digit pairing code shown in their
    control; owners get `{"t":"pair_request"}` and an event `device/pair_request`
    wakes the agent. Approval by an owner device (`pair_approve`) or by the agent
    (`PATCH A/devices/<id>` role `owner`) upgrades the role and sends `{"t":"role"}`.
- A known device (same id + secret) keeps its role across reconnects.

## 8. Delivery and wake

### 8.1 Rule
Delivery never depends on wake. Events are always stored; a wake only prompts the
agent to look and carries a count, never content.

### 8.2 Wake classes and budget
- Class `owner`: `instruction` events from owner devices, `pair_request`.
- Class `page`: `event` with `wake:true`, `rule`, `version_failed`.
- Defaults: `owner_per_hour` 60, `page_per_hour` 12. A sliding one-hour window per
  class counts **delivered wakes**. Wake-eligible events arriving within 3 s of the
  previous delivered wake in the same class merge into it and do not count.
- Over budget: the event is stored with `wake:false, withheld:true`, the class's
  withheld counter increments (reported in `GET A/events` as `withheld` and in the
  wake config), and pages get a presence update so the control can say "the agent
  will see this at its next check".
- `version_failed` wakes at most once per version regardless of budget.

### 8.3 Delivery paths
1. Held long-polls (`GET A/events?wait>0`) are released (after a 300 ms debounce).
2. Webhook, if configured and no long-poll is held: `POST <url>` with headers
   `Content-Type: application/json` and `Authorization: Bearer <token>` if set, body
   `{"source":"tendriller","tendril":"<id>","waiting":<n>,"text":"<n> tendril event(s) waiting on <name>. Read them with GET <A>/events?after=<cursor>","events_url":"<A>/events"}`.
   Debounced 2 s. 10 s timeout. A non-2xx or network error is retried with backoff
   (30 s, 2 min, 10 min).
3. Nothing: the event waits for the agent's next check (schedule or manual).

### 8.4 Presence
Computed by the server, broadcast to pages on change, recomputed by an alarm every
30 s while devices are connected:

```json
{"state":"listening"|"working"|"scheduled"|"not_responding"|"away"|"no_agent",
 "text":"<human label>","last_seen":<ts|null>,"schedule_minutes":n|null,
 "withheld":<n>,"wake":"long_poll"|"webhook"|"schedule"|"none"}
```

- `listening`: a long-poll is held now, or a webhook is configured and the last check-in was within 24 h.
- `working`: a check-in happened within the last 60 s and no long-poll is held, or `POST A/status` set it.
- `scheduled`: schedule hint set; text "checks every N min"; becomes `not_responding` if no check-in for 2 × N + 5 min.
- `not_responding`: a wake was delivered and no check-in followed within `grace_seconds` (default 120).
- `away`: last check-in more than 1 h ago and none of the above; text "last heard from <relative time>".
- `no_agent`: never checked in, or all tokens revoked.

A check-in is any authenticated agent API call. It clears `not_responding`.

## 9. Fast voice layer (owner: voice agent)

Page side (`runtime/src/voice/`):
- `tendril.expose(name, {description, phrases?, params?}, fn)` registers a function
  the voice layer may call. `phrases` are patterns like `"tick *"`, `"next step"`
  (`*` captures the rest as `args.text`). `params` is a JSON Schema object for the
  model-based provider.
- `tendril.voice.start()` / `.stop()` / `.state` and the control's push-to-talk use
  it when at least one function is exposed or the server reports `features.voice`.
- Utterance handling: (1) local phrase matcher over exposed functions; (2) if the
  server has a realtime provider (`features.voice`), the model session with the
  exposed functions as tools; (3) otherwise, or if nothing handled it, send
  `voice_event` with `handled:false` so it becomes an owner instruction, and show
  "Passed to the agent".
- Handled calls send `voice_event` with `handled:true` (recorded, no wake).

Server side (`server/src/voice.ts`):
```ts
export function voiceAvailable(env: Env): boolean;
export async function handleVoiceSession(request: Request, env: Env, ctx: { tendrilId: string; name: string }): Promise<Response>;
// Body: {"instructions"?: string, "tools": [{name, description, parameters}]}
// Returns 200 {"provider":"openai-realtime", ...provider-specific connection info (ephemeral key, URLs)}
// or 501 {"error":{"code":"unavailable"}} when no provider is configured.
```

## 10. Proactive features (owner: push agent)

Server side (`server/src/push.ts`):
```ts
export function pushAvailable(env: Env): boolean;          // VAPID keys configured
export function vapidPublicKey(env: Env): string | null;   // base64url, uncompressed P-256 point
export async function sendWebPush(env: Env, subscription: PushSubscriptionJSON, payload: unknown, opts?: { ttl?: number; urgency?: "very-low"|"low"|"normal"|"high"; topic?: string }): Promise<{ ok: boolean; status: number; gone: boolean }>;
```
`gone: true` (404/410) means the server deletes that subscription. Payload sent to
devices: `{"title","body","url","tag","tendril":"<id>"}`.

Device rules (`runtime/src/rules.ts`), stored by the server, delivered in `welcome`
and `{"t":"rules"}`, evaluated on the device while the page is open:
```json
{"id":"shop","when":{"type":"geofence","lat":…,"lon":…,"radius_m":150,"on":"enter"|"exit"}
              |{"type":"time","at":"HH:MM","days"?:["mon",…]}
              |{"type":"interval","minutes":n},
 "do":[{"type":"notify","title","body"?}|{"type":"event","data"?}|{"type":"state","path":[…],"value":…}|{"type":"navigate","hash":"#…"}|{"type":"say","text"}],
 "once"?:bool}
```
When a rule fires the runtime performs its actions and sends `rule_fired`.
Limits: geofence and time rules only run while the page is open (backgrounding
limit), which the agent instructions must state.

Service worker push handling lives in `runtime/src/sw-push.ts`, imported by
`runtime/src/sw.ts`, exporting `registerPushHandlers(self: ServiceWorkerGlobalScope)`.

### 11.1 Internal runtime contracts

`runtime/src/core.ts` (runtime-core agent) exports:
```ts
export type Bus = { on(type: string, fn: (payload: any) => void): () => void; emit(type: string, payload?: any): void };
export interface Core {
  bus: Bus;                       // emits: connect, disconnect, welcome, presence, say, instruction_echo, role, pair_request, state, rules, reload, error, versions, activity, devices, links, adopt_code
  config: { id: string; base: string; version: number; ws: string; features: Features };
  device: { id: string; role: string; name: string; pending: boolean; pairCode?: string };
  connected: boolean;
  presence: Presence | null;
  transcript: { ts: number; from: "agent" | "user"; text: string }[];
  state: StateApi;                // as tendril.state
  send(data: any, opts?: { wake?: boolean }): Promise<{ seq?: number; queued: boolean }>;
  instruction(text: string, via: "voice" | "text" | "voice_layer"): Promise<void>;
  request(msg: { t: string; [k: string]: any }): Promise<any>; // adds cid, resolves on the reply with that cid
  raw(msg: object): void;         // fire-and-forget (queued while offline when appropriate)
  upload(blob: Blob, opts?: { name?: string }): Promise<{ id: string; url: string }>;
}
export function createCore(cfg: Window["__TENDRIL__"]): Core;
```
`runtime/src/control/index.ts` (control agent) exports `mountControl(core: Core): ControlApi` with `ControlApi = { hide(); show(); position(p) }`.
`runtime/src/voice/index.ts` (voice agent) exports `createVoice(core: Core): { expose(name, opts, fn): () => void; start(): Promise<void>; stop(): void; readonly state: "idle"|"listening"|"thinking"|"unavailable"; handleUtterance(text: string, via: "voice"|"text"): Promise<boolean> }`.
The control's push-to-talk calls `voice.handleUtterance(text, "voice")`; if it returns `false`, the control calls `core.instruction(text, "voice")`.
`runtime/src/rules.ts` (push agent) exports `startRules(core: Core): void`.
`runtime/src/push.ts` (push agent) exports `setupPush(core: Core): { available: boolean; subscribed(): Promise<boolean>; subscribe(): Promise<boolean>; unsubscribe(): Promise<void> }`.
`runtime/src/index.ts` (runtime-core agent) wires them: `createCore` → `createVoice` → `mountControl` → `startRules` → `setupPush`, then defines `window.tendril`. The control receives voice and push via `core.bus` events or by importing a registry: `runtime/src/registry.ts` exports a mutable `{ voice?: Voice; push?: Push }` set by `index.ts` before `mountControl`.
